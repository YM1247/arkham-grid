# 內容新增指南

## 內容設計順序

新增內容時先回答三個問題：

1. 它服務哪個流派或壓力？
2. 它在 2-4 回合普通戰鬥中會觸發幾次？
3. 它是否符合 `NUMERIC_MODEL.md` 的強度區間？

若答案不清楚，先不要加入獎勵池。

## 方塊設計

方塊影響的是「能不能觸發裝備」。

目前基礎盤面不再從全空開始。開局與死盤懲罰後會生成接近可消除的盤面，讓玩家能較快進入 Row / Col 消除與裝備觸發。

### 建議標籤

- `small`：容易填洞，通常較穩定。
- `wide`：偏向補 Row。
- `tall`：偏向補 Col。
- `awkward`：難放，但可能更容易觸發多線。
- `combo`：為特定道具或流派服務。

### 方塊平衡

- 小方塊提高穩定性，降低死盤風險。
- 大方塊提高消除潛力，也提高卡住風險。
- 怪形方塊應該搭配較高獎勵價值，否則玩家會避免選。
- 若一個方塊常造成無合法步懲罰，它必須有明顯的多線消除潛力。
- 普通方塊只放入起始方塊池或基礎池，不作為戰鬥獎勵。
- 方塊獎勵只給特殊方塊，例如帶有流派條件、特殊形狀價值或未來特殊效果的方塊。
- 特殊方塊需在 `blocks.json` 設定 `special: true`，才可以放入 `rewards.json`。
- 特殊方塊可透過 `weight` 控制進入手牌的頻率，並可用 `smart_score_bonus` 影響智慧手牌評分。

### 智慧手牌

目前手牌已加入 v1 智慧抽取。系統會根據目前盤面替方塊池評分，第一張手牌優先提供可直接造成 Row / Col 消除的方塊；若沒有直接消除機會，則優先提供能補接近完成行列的方塊。

- 偵測盤面中差 3-4 格即可消除的 Row / Col。
- 優先提供能填補缺口、降低死盤風險的普通方塊。
- 將玩家構築影響集中在特殊方塊，例如額外形狀、特殊消除規則、或改變候選權重。
- 避免保證每手必定消除，否則盤面壓力會消失；比較好的目標是「常有方向，但仍需選擇」。
- v1 仍保留隨機性：系統會從前幾名候選中抽取，而不是永遠給最高分方塊。
- 特殊方塊若有較高 `smart_score_bonus`，會更容易在它能補洞或消除時被候選系統選中。

## 道具設計

道具影響的是「觸發後得到什麼」。

正式 slot 分類已依 `CORE-001` 簡化為：

- Row：物理，包含攻擊與防禦。
- Col：魔法，包含祝福與詛咒。現行 runtime 仍消耗 Sanity；正式方向已改為常規魔法消耗 MP，待 `MAGIC-001` 後遷移。

`axis_type` 是正式 slot 驗證欄位；舊 `item_type` 僅供資料遷移相容。玩法差異由 `logic`、`effect_scope`、`sanity_cost` 與狀態效果描述。

### 物理 Row：輸出型

- 功能：穩定傷害。
- 適合新手與低風險構築。
- 新增時先落在 8-14 傷害。
- Combo Weapon 可以依 Row 觸發次數或同時消除加成。
- 範圍可為單體、擴散或全體；範圍越大，單一目標數值越低。

### 物理 Row：防禦型

- 功能：護甲、防禦轉換、延長戰鬥容錯。
- 新增時先落在 10-18 護甲。
- 若附帶傷害或治療，護甲值應下降。
- 可設計成「清除越多 Equipment Row，護甲越高」。

### 魔法 Col：支援型

- 功能：治療、穩定、狀態支援。
- 治療基準 6-12。
- 現行 Prayer 同樣消耗 Sanity；改用 MP 後仍需以 MP 成本或其他條件避免無風險補血。
- 可設計成「本回合已觸發 Curse 時，額外恢復少量 Sanity」。

### 魔法 Col：高風險輸出型

- 功能：高效率輸出、特殊連動、風險決策。
- 現行需支付 Sanity；正式版常規成本將改為 MP，只有特殊秘技保留 Sanity 代價。
- 小型 3、中型 6、大型 10。
- 若 Curse 沒有比 Weapon 更強，就不值得存在。
- 若 Curse 過強，應提高成本或加入條件。

## Combo 設計

強連動流派是本專案接下來的道具方向，但每個 combo 都需要清楚觸發條件。

推薦先做的 combo 類型：

- Row + Col 同時消除：追加傷害或護甲。
- 本回合已觸發高風險魔法：後續支援魔法獲得額外效果。
- Sanity 低於 30：Curse 變強，但可能追加風險。
- 清除特定區域：例如物理 Row 追加傷害、魔法 Col 追加魔法效果。
- 方塊標籤互動：使用 `wide` 或 `tall` 方塊觸發額外效果。

## 敵人設計

敵人影響的是「玩家被迫做什麼取捨」。

### 普通敵人

- HP：30-100，依 run 進度提高。
- 攻擊：8-18。
- 意圖：先以攻擊為主，逐步加入重擊、防禦、Sanity 壓力。
- 敵人資料不包含 `reward_tier`；關卡資料會根據所有敵人的 `tier` 計算獎勵級別。

## 多敵人與目標

- 戰鬥可同時放置多名敵人。
- 玩家點擊敵人來鎖定目標。
- 道具效果以鎖定目標為中心結算。
- `effect_scope`：
  - `single`：鎖定目標。
  - `spread`：鎖定目標與左右各一。
  - `all`：所有存活敵人。
  - `self`：使用者自身。

## 異常狀態

- `strength`：力量，攻擊傷害增加。
- `weak`：虛弱，攻擊傷害減少。
- `hard`：堅硬，獲得護盾增加。
- `fragile`：脆弱，獲得護盾減少。
- `regen`：再生，回合結束時回復 HP。
- `poison`：中毒，回合結束時受到傷害。
- 狀態可疊加，預設在該角色回合結束時 -1。

### Sanity 壓力敵人

- 不應每回合都大量扣 Sanity。
- 建議採用可預期模式，例如 `attack`, `sanity_attack`, `attack`。
- Sanity 攻擊常用區間：5-10。

### 菁英敵人

- HP 是同階普通敵人的 1.5-2 倍。
- 攻擊提高 20-40%。
- 應該迫使玩家使用 combo 或冒 Sanity 風險。

## 獎勵池設計

每個獎勵應該有清楚目的：

- 補穩定性：特殊小方塊、護甲、治療。
- 提高輸出：Weapon、Curse。
- 建立流派：條件加成、Sanity 互動、形狀互動。

避免：

- 純數值完全優於另一個同級道具。
- Curse 傷害太低導致沒人想選。
- 特殊方塊只增加卡手風險但沒有 combo 報酬。
- 三選一全部都是同類型效果。

## 玩家成長規範

玩家成長應強化構築效率，而不是頻繁恢復或提高核心壓力資源。

- 普通戰鬥三選一獎勵不應提供 HP 回復、Sanity 回復、HP 上限、Sanity 上限或 AP 上限。
- HP / Sanity 回復應屬於休息、事件、Boss 後獎勵或高代價選擇。
- HP / Sanity 上限增加應非常稀有，且需要明確的節點或代價。
- AP 上限增加是極高影響成長，會改變整個盤面節奏，應保留給關鍵構築或特殊節點。
- 常規成長應優先使用特殊方塊、裝備替換、裝備升級、稀有度提升或手牌規則變化。

## JSON 欄位規範

### `items.json`

- `tags`：流派與效果標籤，例如 `gun`、`curse`、`sanity_scaling`。
- `tags` 只給特殊流派或 combo 使用；普通數值道具保持空陣列。
- `rarity`：`common`、`uncommon`、`rare`。
- `trigger_hint`：給企劃與 UI 使用的觸發條件說明。
- `balance_cost`：內部強度分數。
- `effect_scope`：`single`、`spread`、`all`、`self`。
- `status_effects_self` / `status_effects_target`：狀態效果陣列。

### `blocks.json`

- `tier`：內容階段。
- `weight`：抽牌權重。
- `tags`：形狀與流派標籤。
- `special`：是否為可作為獎勵的特殊方塊。
- `smart_score_bonus`：智慧手牌評分加成。

### `enemies.json`

- `id`：唯一 ID。
- `tier`：敵人階段。
- `speed`：不顯示給玩家的行動速度。
- `intent_pattern`：引用 `intents.json` 的獨立意圖循環。
- `sanity_pressure`：是否會施加 Sanity 壓力。
