# 未決問題登錄表

## 使用方式

本文件只保存需要玩家決定的企劃、內容、產品與高影響技術方向。程式或現有資料能直接回答的事實不列入問題。

- 問題以固定 ID 供 Roadmap、TODO 與開發紀錄引用。
- 玩家已填入單一明確答案的問題移入「已決定」。
- 只有候選方向、仍標示「待回覆」的問題保留在「待確認」。
- 未回答的問題不得由開發者自行選擇答案；可先完成不依賴答案的架構與測試。
- 2026-09-06 整理時，只將玩家明確填入的語言、世界觀與發布平台三筆回覆移入「已決定」；其餘「可選方向」仍只是建議，不當作玩家決策。
- 2026-09-06 第二次整理時，將玩家新填入「玩家回覆」欄的 Meta、存檔、平衡、可及性、內容與發布答案正規化後移入「已決定」；不完整涵蓋原問題的回答會拆出新的待確認問題。

## 已決定

### 架構與核心分類

- `ARCH-001`：JSON 管理內容 ID、組合、數值與資源引用；`.tres` 管理效果行為原型。`ContentRegistry` 依 JSON 引用複製 `.tres`，再套用數值建立 runtime Resource。
- `CORE-001`（已由 `CORE-002` 至 `CORE-005` 取代）：舊 Row／Col 裝備分類不再使用。
- `CORE-002`：保留完整 Row／Col 消除，但改由被消除的方塊效果格觸發咒文。
- `CORE-003`：方塊形狀與咒文獨立抽取，任何咒文都可能附著於任何形狀。
- `CORE-004`：每塊方塊只有一個效果格；同格位於 Row／Col 交會時仍只觸發一次。
- `CORE-005`：移除裝備／法術雙分類與 Row／Col 裝備槽；所有可觸發效果統稱「咒文」。

### 棋盤與回合既有規則

- `BOARD-001`：智慧手牌每手至少提供一張有明確消除方向的方塊；優先直接消除，其次推進接近完成的 Row／Col。
- `BOARD-002`：友善盤面使用程序生成，不採固定模板。
- `BOARD-004`（2026-09-07 修訂）：特殊形狀不重複取得；以低基礎權重及低智慧評分加成避免星點石板壟斷手牌。
- `BOARD-003`：盤面在戰鬥、事件、商店、休息與獎勵等 Run 節點間全部保留；開始全新 Run 時才建立新的程序友善盤面。
- `BOARD-005`：玩家不能手動旋轉方塊；方塊抽到手上時由系統隨機決定方向。
- `BOARD-006`：回合結束時保留所有未使用手牌及其方向，下一回合只補足缺少數量；棄置或指定保留只由特殊道具／效果提供。
- 棋盤固定為 8x8；完整 Row／Col 會消除，所有被消除的效果格各觸發一次咒文；不同咒文使用自己的盤面圖標與分類色。
- 棋盤跨戰鬥保留；新戰鬥不清空盤面。
- 開局與死盤懲罰後使用接近可消除的友善盤面。
- 手牌沒有任何合法放置時扣除 10 Sanity、清除盤面、重建友善盤面並重抽。
- 每個方塊固定消耗 1 AP；AP 歸零後不能拖動方塊。
- AP 由 `data/player.json` 控制，原型基準為每回合 5 點。
- 玩家回合開始時清空護甲，讓本回合取得的護甲抵擋接下來的敵人行動。

### HP、Sanity 與狀態既有規則

- 玩家初始 HP 80；Sanity 上限暫定 100、初始值暫定 70。
- Sanity 歸零直接導致 Run 失敗；低 Sanity 瘋狂效果會在歸零前發生。
- MP 上限 100；調查員原型初始 70，每完成一個節點固定回復 35。MP 不足時照常觸發咒文，改以相同數量的 Sanity 代付。
- 普通戰鬥三選一不提供 HP／Sanity 回復或上限，也不提供 AP 上限。
- 力量／虛弱調整攻擊；堅硬／脆弱調整護甲收益；再生／中毒在角色回合結束觸發。
- 狀態在各角色回合結束時觸發，並在完整敵我一輪結束時統一衰減 1。
- 切換戰鬥時清除玩家暫時狀態與護甲，但保留 HP、Sanity、MP、盤面、手牌、方塊池與咒文池。

### 戰鬥規則

- `COMBAT-001`：意圖包含攻擊、重擊、防禦、Sanity 攻擊、對玩家 debuff、對自身 buff；UI 只預告意圖類型，不顯示精確數值。
- `COMBAT-002`：多名敵人依內部速度值由高至低行動；同速依生成順序，速度不顯示給玩家。
- `COMBAT-003`：擴散效果依存活敵人的相鄰順序計算，跳過死亡空位。
- `COMBAT-004`（2026-09-07 更新）：目前鎖定目標死亡後，自動鎖定 encounter 原始順序中的第一名存活敵人；同一次方塊放置後續觸發的效果使用新目標。
- `COMBAT-005`：狀態在角色回合末觸發，完整敵我一輪結束時統一衰減。
- `COMBAT-006`：同一結算序列中玩家與最後一名敵人同時死亡時，玩家失敗。
- `COMBAT-007`：敵人與玩家完整對稱支援護甲及力量、虛弱、堅硬、脆弱、再生、中毒六種狀態。
- `COMBAT-008`：一場 encounter 最多同時出現 5 名敵人。

### 咒文、敵人與獎勵既有規則

- 戰鬥可同時出現複數敵人，玩家可點擊鎖定目標。
- 效果範圍包含單體、擴散、全體與自身。
- 敵人不保存 `reward_tier`；獎勵強度由關卡難度決定。
- 普通方塊屬於基礎池，不作為戰鬥獎勵；方塊獎勵只出現特殊方塊。
- 咒文獎勵直接加入咒文池；後續抽出的方塊會從池中獨立取得咒文與效果格。

### 局內成長與獎勵

- `GROWTH-001`：咒文可保留稀有度與升級鏈，但不再配置到裝備槽。
- `GROWTH-002`：稀有度同時控制數值、條件複雜度與出現階段。
- `GROWTH-003`：特殊方塊主要透過戰鬥或消除效果成長。
- `GROWTH-004`：咒文與手牌規則由獎勵池控制；特殊形狀每種最多解鎖一次。
- `REWARD-001`：先決定關卡難度，再由難度決定敵人數量／強度及獎勵 tier。
- `REWARD-002`（已由核心改版取代）：不再使用背包與合法裝備槽；咒文直接加入池。
- `REWARD-003`：咒文可重複取得以改變池內權重；特殊形狀不可重複取得。
- `REWARD-004`：預設不可重抽；可跳過並換成局內金錢，特殊道具未來可例外提供重抽。
- `REWARD-005`：候選只依權重隨機，不固定候選角色分工。

### Run、地圖與節點

- `RUN-001`：單局目標約 30 分鐘；實際場數依戰鬥時長測試，5–8 場暫作原型基準。
- `RUN-002`：地圖可有多個起點與中段分支，最終匯聚到單一 Boss；時間允許時可擴充複數章節。
- `RUN-003`：Run 使用可顯示與重用的種子；一般模式可查看但不能輸入，自訂模式可輸入與分享。
- `RUN-004`：擊敗最終目標後直接通關；高難度另開模式，不接無限循環。
- `NODE-001`：第一版節點包含普通戰鬥、菁英、Boss、事件、商店與休息。
- `NODE-002`：Boss 前必定出現可無代價回復的休息；Boss 後可無代價回復並可能提供帶小代價的上限提升；事件與獎勵節點可用 HP／Sanity 互換、負面狀態、負面方塊或負面咒文作為代價。

### Sanity 與瘋狂

- `SANITY-001`：低 Sanity 採兩到三個階段。
- `SANITY-002`：第一批瘋狂使用影響多個系統的混合效果池。
- `SANITY-003`：瘋狂效果可疊加但不可重複。
- `SANITY-004`：Sanity 回復到對應門檻以上時解除該階段瘋狂效果。
- `SANITY-005`：玩家選擇魔法或事件前可完整預覽低 Sanity 後果。

### 平台與顯示

- `UX-001`：第一目標平台與操作方式為 PC 鍵盤滑鼠。
- `UX-002`：第一版以單一 16:9 基準解析度與比例為正式支援範圍。
- `UX-003`：程式與內容管線預留多語系；第一批實際製作繁體中文與英文。

### 世界觀與發布

- `CONTENT-004`：世界觀採原創與公版神話元素混合，以克蘇魯神話為基底。
- `CONTENT-005`：正式內容只使用可驗證的公版或已授權素材，其餘名稱、敘事與資產改為原創。
- `CONTENT-001`：Demo 與正式版內容量採逐里程碑定義，不先承諾固定總量。
- `CONTENT-002`：敘事採對話與場景描述混合呈現。
- `CONTENT-003`：內部階段先使用 AI 生成的簡約像素風奇幻神話素材，正式版本再替換為精緻素材；氛圍參考 HD-2D 式層次與克蘇魯背景，但不直接複製特定作品資產。
- `CONTENT-006`：事件採多選項結構，代價與結果由資料定義。
- `CONTENT-007`：商店與休息沿用事件選項 schema，共用資料化代價／結果元件。
- `RELEASE-003`：最終發布目標為 Steam；早期測試與交付可先使用 itch.io 等平台。
- `RELEASE-001`：下一個交付目標為內部原型。
- `RELEASE-002`：第一版效能基線以低階筆電為目標。
- `RELEASE-004`：允許收集匿名統計與當機回報。

### 局外系統與存檔

- `META-001`：局外養成以解鎖內容為主，永久數值為輔。
- `META-002`：永久成長不直接提高 HP、Sanity 或 AP；以角色差異取代常態壓力資源成長。
- `META-003`：提供不同角色／職業，以起始配置加專屬規則形成差異。
- `META-004`：貨幣、解鎖與成就使用單一共享進度。
- `SAVE-001`：Run 在節點進入前與完成後自動保存。
- `SAVE-002`：第一版使用單一自動存檔槽。
- `SAVE-003`：進入節點即鎖定進度，不允許回讀舊節點重選結果。
- `SAVE-004`：內容引用失效時採版本化自動遷移；遷移失敗仍須保留備份並拒絕覆寫。

### 可及性與資源平衡

- `UX-004`：第一版需要完整焦點導覽與核心流程鍵盤操作。
- `BALANCE-001`（代付例外已由 `MAGIC-002` 補充）：MP 作為常規咒文的主要消耗資源；Sanity 是更珍貴、代價更高的資源，不再因一般 Col 消除固定扣除。
- `MAGIC-001`（支付不足規則已由 `MAGIC-002` 取代）：MP 上限 100，初始值依職業；每完成節點固定回復。調查員原型採 70 初始、每節點回復 35。
- `MAGIC-002`（2026-09-08 修訂）：MP 不足時不讓咒文失效，改以該咒文的完整 MP 成本等量扣除 Sanity；Sanity 不足會依既有規則導致 Run 失敗。
- `UX-005`：每種咒文必須在手牌與盤面使用可直接辨識的獨立圖標與效果分類色，不把 hover tooltip 當作主要辨識手段。
- `BALANCE-002`：常規咒文不提供直接 HP 治療或再生；HP 回復主要來自休息、商店與高代價節點。
